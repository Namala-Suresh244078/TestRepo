Stage C – Step Functions implementation
Only after C08 design is reviewed:

Act as a Senior AWS Serverless Architect.

Design an AWS Step Functions Standard Workflow to orchestrate the existing AWS FIS experiments.

The workflow must support configurable experiment types:

- AZ_FAILURE
- DATABASE_FAILOVER
- CPU_STRESS
- MEMORY_STRESS
- NODE_DRAIN

Required workflow states:

1. Validate input.
2. Perform pre-experiment health checks.
3. Validate AWS resource availability and safety conditions.
4. Optionally create a database snapshot based on the experiment type.
5. Start continuous application health monitoring.
6. Start the selected AWS FIS experiment.
7. Capture the FIS experiment ID.
8. Monitor experiment execution until completion, failure or timeout.
9. Collect infrastructure and application metrics.
10. Validate EKS node and pod recovery.
11. Validate database and application recovery.
12. Generate consolidated execution results.
13. Store the report and supporting evidence in S3.
14. Notify the execution outcome.

Requirements:

- Use retry and catch handling.
- Implement explicit timeouts.
- Record inputs, outputs and timestamps for each state.
- Separate FIS execution status from application resilience status.
- Never report PASS solely because FIS completed successfully.
- Ensure the workflow cannot start an experiment when pre-checks fail.
- Ensure failure paths capture evidence before ending.
- Use least-privilege IAM permissions.

First inspect existing project conventions and propose the required file structure.

Do not modify files yet.

Provide the Step Functions ASL definition and supporting Lambda design.
