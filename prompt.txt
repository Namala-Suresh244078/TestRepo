Story 357272 - Delete User Function

The existing delete endpoints were originally intended for this functionality and should be reused.

Proceed with implementation using the existing controllers, services and repositories.

Requirements:

1. Reuse existing endpoints.
2. Do not create new delete APIs.
3. Convert hard delete behavior to soft delete:
   - Set user status to INACTIVE.
   - Persist changes.
   - Do not remove records.

4. Authorization rules:

Portal Admin:
- Can delete Portal Users assigned to their portal.
- Can delete Portal Admins assigned to their portal.
- Cannot delete users outside their assigned portals.

Portal Agent:
- Can delete Portal Users from any portal.
- Can delete Portal Admins from any portal.

5. Ensure inactive users do not appear in user listing/search APIs.

6. Reuse existing permission framework and authorization patterns already present in the codebase.

7. Minimize code changes.
8. Do not refactor unrelated code.
9. Preserve existing API contracts.
10. Add or update unit tests only where necessary.

- Files to modify
- Reason for modification
- Risk level

Then implement the changes.
